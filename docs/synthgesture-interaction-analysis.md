# SynthGesture 的和弦交互分析

读取日期：2026-09-29。范围是 **Gesture Chords**，不把站内 Piano、Theremin、Flute、Drums 等模式混为同一套手势。本次静态阅读官方教程和公开网页加载的客户端代码；未执行下载代码、未试听参考视频音轨，也未测量其真人识别率或延迟。以下是交互事实与独立设计建议，没有把第三方实现复制进 CHORA。

## 结论：它把音乐拆成几个可以同时演奏的维度

它的效率主要来自双手的分工：左手选择根音与大／小和弦，右手选择配器、八度，同时连续控制力度和滤波。一次摆手就可以改变多个音乐参数，不必在屏幕上依次找按钮。入门预设可以分别锁定大／小模式和配器，等熟练后再开放这些维度。界面中心持续显示最终和弦，让演奏者确认的是音乐结果。

这比原 CHORA 的“左手选七个固定顺阶和弦，右手只管力度与明亮度”多了**和弦性质、转位、扩展音和八度**。不过这些维度仍有手部联动、遮挡和识别延迟，不能仅凭功能数量断言真人演奏一定更稳。

## 精确手势映射

| 动作 | 实际效果 | 静态证据 |
| --- | --- | --- |
| 左手伸出 1–5 根手指 | I–V；计数包含拇指，并不限于固定的“从食指依次展开”手型 | `aC`、`eC`、`$S` |
| 左手仅食指＋小指 | VI；该特例优先于普通“两指” | `aC`；完整指南也明确说明 |

| 左手手腕倾斜 | 大／小和弦模式；可用设置锁定 | `nC`、`modeControl`、演奏循环 |
| 右手 1–4 根非拇指手指 | 选择下表的四种配器 | `iC`、`dC`、`xS` |
| 右手拇指向外伸展 | 全部音降一个八度，独立于其余四指计数 | `eC`、`thumbDown`、频率除以 2 |
| 右手抬高／降低 | 连续控制音量 | `rC`、`setVolume` |
| 右手手腕倾斜 | 连续控制低通滤波截止频率与共振 | `nC`、`updateFilterSweep` |
| 左手无有效指型 | 经稳定确认后释放和弦 | `cC`、演奏循环 |
| 右手握拳／仅伸拇指 | 跟随手指配器时，非拇指计数为 0，静音；**固定配器时握拳不一定静音** | `qualityControl` 覆盖计数；演奏循环以配器编号 ≥1 发声 |
| 右手离开画面 | 当帧要求音量归零，再由音量斜坡衰减 | 演奏循环；不能把左手的丢失宽限套用到这里 |

“三和弦”指和弦的音高类别，并不等于只有三条振荡器。其默认三和弦实际上是四声部开放排列：根音、五度、高八度根音、高八度三度。

| 右手非拇指数 | 大模式 | 相对根音的半音数 | 小模式 | 相对根音的半音数 |
| --- | --- | --- | --- | --- |
| 1 | 大三和弦，开放排列 | 0, 7, 12, 16 | 小三和弦，开放排列 | 0, 7, 12, 15 |
| 2 | 第一转位 | 4, 7, 12, 16 | 第一转位 | 3, 7, 12, 15 |
| 3 | 大七和弦 | 0, 4, 7, 11 | 小七和弦 | 0, 3, 7, 10 |
| 4 | 属七和弦 | 0, 4, 7, 10 | 减七和弦 | 0, 3, 6, 9 |

这里的手指数量选择的是**同时发声的音列**，没有发现这一映射自动生成琶音或节奏型的证据。

### “大／小模式”并非自动顺阶和声

客户端 `yS`、`bS` 的七个根音偏移是 `0, 2, 4, 5, 7, 9, -1`。VII 位于主音下方一个半音，而不是上方 11 个半音。根音集合不随大／小模式改变；模式只改变三度与右手配器。因此以 C 为参考音、锁定大模式时，II 是 **D 大和弦**，并非 C 大调内的 Dm；小模式也不是自动改成 C 自然小调音阶。

UI 引导中的七级音名表使用上行 `0, 2, 4, 5, 7, 9, 11`，与实际 VII 的音级类别相同、音区不同。CHORA 若采用同类自由配和弦，必须把“顺阶伴奏”和“自由大／小和弦”说明清楚。

## 连续控制与稳定机制

| 层级 | 本次公开构建的实际行为 | 对演奏的含义 |
| --- | --- | --- |
| 手指伸直 | 非拇指用指尖 y 小于 PIP 关节 y；拇指用指尖与上一关节的横向关系，并区分角色 | 适合手掌大体竖直的指型；这不是对任意旋转鲁棒的关节角度识别 |
| 关键点平滑 | 每个新视频帧向新位置移动 55%；腕点跳动超过归一化距离 0.2 时重置；缺失手部清空其历史 | 削弱抖动，避免大位移拖影；没有单独证明其实际端到端延迟 |
| 左腕大／小 | 取腕点 x 与中指、无名指 MCP 的 x 区间；在区间内取 0，超出距离除以 0.12 并限制到 −1…1。左手数值 ≥0 为大，<0 为小 | 中性区归到大模式；未发现进出阈值不同的 Schmitt 迟滞 |
| 右腕音色 | 使用同一几何量并翻转符号；中性截止 1200 Hz/Q 0.7；负向到 250 Hz/Q 2.2，正向到 5000 Hz/Q 5.2；参数时间常数 40 ms | 小幅手腕动作即可带出很显著的暗／亮与共振变化 |
| 右手音量 | 腕点 y 在 0.95…0.05 映射到 0…1；输出增益用 50 ms 线性斜坡 | 从抬手到声音渐入，动作和听感有直接联系 |
| 离散变化 | 整组“级数＋大／小＋配器＋八度”连续稳定 100 ms 才提交 | 把换手型中的短暂中间状态过滤掉；任一维度持续波动会延迟整组提交 |
| 丢失宽限 | 候选变空时，距离最近有效候选不足 50 ms 暂用旧候选，之后还需通过 100 ms 提交窗口 | 左手丢失约 150 ms 后释放是代码推导，具体受帧时刻影响；不是所有设备精确 150 ms |

有两个阅读时容易误判的细节：

1. `tC` 有一个简单的 MCP9 与腕点 x 比较，但实时演奏循环随后以 `nC` 的腕倾结果重新确定大／小；不能只读 `tC` 就认定最终阈值。
2. 跟踪器的通用 `left/right` 字段经 `XS` 翻转 handedness，但 Chords/Theremin 实时循环又从原始类别名经 `ZS` 重新选角色。官方文章的“镜像修正”描述不足以确定每种模式的最终左右手行为。CHORA 应以自己的 MediaPipe 验证与角色交换功能为准。

## 设置与循环为什么有用

设置可独立选择左手的“Fingers + wrist tilt / Scale notes only”和右手的“Follow finger layout / Use a fixed style”，并分别保存。Easy C-major 预设固定大模式与第一种配器、C 参考音、96 BPM；公开构建预设是 2 小节，而教程练习主动要求改为 4 小节。Dreamy sevenths 固定小模式与第三种配器、D 参考音、78 BPM、4 小节。预设改变的是演奏难度和音乐范围，不能据此认为更換了声音合成器。

循环器有四条轨道，每拍四格、一小节预备拍；一轮录完自动开始循环，并尝试选中下一条空轨。每轨有音量、静音、独奏，格子能停用、恢复或指定和弦。Export 导出音频 WebM；顶端 Record 录制摄像头画面与合成声音，格式由浏览器支持决定。快捷键 R、1–4、M、S、Delete 降低录制时寻找界面控件的次数。[证据：完整指南；`Cb=4`、`wb=4`、`startCountIn`、`finishRecording`、`placeChord` 等。]

代码显示循环先记录参数帧，再按格子选取有效帧、合并同音列片段并离线渲染。它不是无损保存全部连续动作的手势自动化轨；合并片段可能简化音量和音色变化。循环的核心价值是先铺和声、再腾出双手和注意力唱歌或叠加声部，而不是要求演奏者一次完成所有动作。

## 交互效率来自哪里，以及要付出什么

| 演奏任务 | 参考站的动作 | 省下的屏幕操作 | 仍需控制的代价 |
| --- | --- | --- | --- |
| I → IV → V | 左手变指型，右手可保持原姿势 | 每次不用重新找根音按钮 | 1→4 指会经过 2、3；必须过滤换形中间态 |
| D → Dm | 左手根音不变，只倾腕 | 不用切换调性或另找 Dm | 腕倾会改变投影和指型可见性；与根音并非完全独立 |
| C → C/E → Cmaj7 | 左手保持 I，右手 1→2→3 指 | 不必依次打开和弦菜单、找转位和七和弦 | 这是指定音列，并非自动最短声部移动；右手还要维持力度 |
| 同和弦进入低音区 | 右手其余手指保持，展开拇指 | 不用寻找八度控件 | 拇指牵动手掌，必须避免一帧误判造成八度跳跃 |
| 边唱边减少控制负担 | 固定性质／配器，或先录好一层循环 | 减少同时照顾的维度 | 固定设置降低可即时演奏的变化范围；循环需时值和录制管理 |

对初学者而言，效率应衡量为“预期音乐变化所需动作少、误触可恢复”，不能只数一个姿势能带动几个参数。参考教程先锁住腕倾和配器，先练 I–IV–V–IV，再逐项开放，是一种降低同时决策数量的方法。对 CHORA，顺阶和弦选项有价值：C 调 I–ii–V–vi 可以直接得到 C–Dm–G–Am；若照参考锁定大模式则会变成 C–D–G–A，用户必须主动决定何时改小和弦。

右手同时承担配器、八度、力度、亮度，因此它是主要协调瓶颈。界面应持续显示最终和弦、八度和配器，待确认时维持已接受的声音。练习时先固定高度只换配器，再加入抬手和倾腕，才能判断问题来自姿势识别还是多维协调。

## 本轮 CHORA 已实现的逻辑边界

- VI/VII 使用确认后的参考指型；I–V 保留固定完整指型，未照搬任意指数组合。原 🤙／L 不再匹配。
- `harmony.ts` 原三参数调用仍产生原有顺阶三／七和弦；新增第四参数独立控制大／小性质、四种配器及低八度。第一转位显示含低音的名称，例如 C/E；自由小模式的四指色彩是 Cdim7，不是 Cm7。
- 顺阶模式中显式使用开放／第一转位保留每一级原三度与五度，七级仍为减五度；显式选择属七／减七是可离调的色彩变化。界面明确区分顺阶伴奏和自由配和弦；按用户最新反馈，默认开启左腕切大／小，顺阶仍可选择。
- 左腕模式采用 CHORA 自有角度约 ±12° 迟滞、140 ms 确认；右手配器与拇指组成一个候选并确认 140 ms，避免先换配器再误跳八度。模式、根音、右手配器各自确认，不声称跨手同时变化一定在同一帧提交。
- 首次尚未接受的修饰参数保持缺省；使用手势配器／腕倾的界面应等待相应字段被确认再发声，不能把缺省猜作实际姿势。已接受后的短暂候选继续保留原值。
- 任一手丢失或握拳、右手只伸拇指立即请求静音并清空参数接受状态；这条 CHORA 规则对固定配器同样适用。
- 相关 27 项逻辑回归通过。真实设备延迟还包括视频帧率、推理、85 ms 控制平滑、声卡缓冲和声音包络，不能由 140 ms 确认窗口推断实际演奏延迟。

## 右腕效果与左腕入口修正

用户实测反馈右腕没有明显音色变化，并指出参考站左腕切大／小。检查确认三条问题：左腕功能已实现但藏在非默认选择；旧右腕只给预设亮度附加±0.25，滤波截止多落在和弦主能量上方；归一化横纵坐标未乘视频宽高比，使640×480中实际30°侧倾仅算成23.4°。

当前默认开启左腕大／小，提供独立开关和角度/已确认性质显示；关闭可锁住当前性质。右腕使用独立 `wristTone` 处理，约±30°覆盖0–1，回中恢复原色，预设明亮度不再随它变化。图像角度按真实宽高比还原，原始骨架坐标不改变。这里的侧倾是镜像画面中的左右偏转，不是前后翻掌或3D旋转全方向控制。

## 后续设计建议

- 以真实演唱检查右手同时控制配器、力度与亮度的负担，决定是否要增加独立锁定某个维度的入口。
- 在用户试听三种声音后再细调清晰度、混响和起音，避免将客观差异视为艺术质量结论。
- 循环仍是后续可独立验收的功能：四轨、网格编辑、音视频导出会明显扩大项目。本轮不加入循环或录制，先用真实演唱决定是否需要它们或踏板/锁定和弦。

这些是 CHORA 的独立设计建议，不是对 SynthGesture 已验证功能的补充。真人手感、延迟和音色仍须用实际摄像头、麦克风与耳机试听验收。
